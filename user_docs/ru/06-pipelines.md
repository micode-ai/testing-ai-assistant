# Пайплайны и тестовые прогоны

## Пайплайны

Пайплайн — это конфигурация для автоматического запуска тестов. Он определяет, какие типы тестов выполняются, в каком порядке и при каких условиях.

### Создание пайплайна

1. Откройте проект → «Пайплайны»
2. Нажмите «Новый пайплайн»
3. Настройте:
   - **Название** — имя пайплайна
   - **Типы тестов** — выберите один или несколько:
     - Unit-тесты
     - Интеграционные тесты
     - E2E-тесты
     - Нагрузочные тесты (Load)
     - Тесты безопасности (Security)
   - **Триггеры** — условия запуска (push, PR, вручную)
   - **Параметры** — специфичные настройки для каждого типа тестов
4. Нажмите «Создать»

### Включение / Отключение

Пайплайн можно временно отключить без удаления:

1. Откройте пайплайн
2. Используйте переключатель «Активен» / «Неактивен»

Или через API:
```
POST /pipelines/:id/toggle
```

### Типы тестов

| Тип | Описание | Инструменты |
|-----|----------|-------------|
| **Unit** | Модульные тесты отдельных функций | Jest |
| **Integration** | Тесты взаимодействия компонентов | Jest, Supertest |
| **E2E** | Сквозные тесты пользовательских сценариев | Playwright, Cypress |
| **Load** | Нагрузочное тестирование | k6, Artillery |
| **Security** | Тестирование безопасности | OWASP ZAP, Snyk |

### API пайплайнов

```
POST   /pipelines                    — Создание пайплайна
GET    /pipelines?projectId=<id>     — Список пайплайнов проекта
GET    /pipelines/:id                — Детали пайплайна
PATCH  /pipelines/:id                — Обновление конфигурации
DELETE /pipelines/:id                — Удаление
POST   /pipelines/:id/toggle         — Включение/отключение
```

## Тестовые прогоны

Тестовый прогон (Test Run) — это однократное выполнение пайплайна. Он содержит результаты всех тестов, метрики покрытия и артефакты.

### Запуск

#### Автоматический (через вебхук)

При push или pull request в подключённый репозиторий система автоматически:

1. Получает событие от Git-провайдера
2. Находит активные пайплайны проекта
3. Создаёт тестовый прогон
4. Передаёт его в Temporal для выполнения

#### Ручной

1. Откройте пайплайн → «Прогоны»
2. Нажмите «Запустить»
3. При необходимости укажите ветку или коммит
4. Подтвердите запуск

Или через API:
```
POST /test-runs
Body: { "pipelineId": "...", "branch": "main", "commit": "abc123" }
```

### Жизненный цикл прогона

```
PENDING → RUNNING → PASSED / FAILED / ERROR
                  ↘ CANCELLED
```

| Статус | Описание |
|--------|----------|
| `PENDING` | Прогон создан, ожидает выполнения |
| `RUNNING` | Тесты выполняются |
| `PASSED` | Все тесты прошли успешно |
| `FAILED` | Один или несколько тестов не прошли |
| `ERROR` | Произошла ошибка выполнения |
| `CANCELLED` | Прогон отменён пользователем |

### Отмена прогона

```
POST /test-runs/:id/cancel
```

### Результаты

Каждый прогон содержит:

- **Результаты тестов** — статус каждого теста (passed/failed/skipped)
- **Логи** — вывод тестового фреймворка
- **Время выполнения** — длительность каждого теста и общее время
- **Покрытие кода** — процент покрытия (если включён сбор покрытия)
- **Артефакты** — скриншоты, отчёты, загруженные в MinIO

### Обновления в реальном времени

Pipeline Service поддерживает SSE (Server-Sent Events) для отображения прогресса в реальном времени:

- Изменение статуса прогона
- Завершение отдельных тестов
- Обновление процента выполнения

Dashboard и мобильное приложение автоматически подписываются на SSE-поток.

### Покрытие кода

Снимки покрытия сохраняются для каждого прогона:

- Общий процент покрытия
- Покрытие по файлам
- Тренды покрытия во времени

### API тестовых прогонов

```
POST   /test-runs                    — Создание и запуск
GET    /test-runs?pipelineId=<id>    — Список прогонов
GET    /test-runs/:id                — Детали прогона с результатами
POST   /test-runs/:id/cancel         — Отмена прогона
```

## Temporal Workflows

Тестовые прогоны оркестрируются через Temporal:

1. **Pipeline Service** создаёт запись о прогоне и отправляет событие в Redpanda
2. **Test Runner** (Temporal Worker) получает событие и запускает workflow
3. Workflow выполняет шаги: клонирование, установка зависимостей, запуск тестов
4. Результаты и артефакты отправляются обратно через события
5. **Pipeline Service** обновляет статус и результаты

Вы можете отслеживать workflows в **Temporal UI**: http://localhost:8233
